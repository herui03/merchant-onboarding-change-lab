# Defect log (real defects found during development)

Only defects that were actually observed are listed. Each product defect was reproduced
**before** it was fixed, and each has a regression test that fails on the old code. Test-harness
mistakes are listed separately, because they were bugs in the tests, not in the product.

## Product defects

| ID | Found by | How it was found | Symptom (reproduced) | Root cause | Fix | Regression test | Status |
|---|---|---|---|---|---|---|---|
| DEF-001 | Codex source review R3-01 | Reported by Codex, then reproduced by Claude on a temporary seeded database through the real service | `remove_document("jordan", "MOB-0006", 2**100, …)` raised a raw `OverflowError: Python int too large to convert to SQLite INTEGER` instead of the documented 404. The transaction rolled back, so the fingerprint was unchanged, but the HTTP layer would have returned 500. | The document-id guard rejected bools, non-ints and values < 1, but had no upper bound before binding to SQLite. | One documented id range, `1..2^31-1` (`contracts.ID_MAX`, `is_valid_id`), used for document, revision and evaluation ids. | `test_out_of_range_document_id_is_a_404_not_a_crash` (8 cases), `test_out_of_range_revision_and_evaluation_ids_are_422` (4 cases). HTTP path: `test_def001_huge_ids_over_http_are_404_not_500`. Verified failing on the old guard. | Fixed |
| DEF-002 | Codex source review R3-02 | Reported by Codex, then reproduced by Claude with its exact steps through the real service | Add document A (id 26) → remove A → add replacement B → B also got id 26 → a stale "remove 26" **deleted B**. The fingerprint changed. | `draft_document.id` was a plain `INTEGER PRIMARY KEY`. SQLite reuses the highest deleted rowid, and draft documents are the only deletable rows. | `INTEGER PRIMARY KEY AUTOINCREMENT` on `draft_document`, so ids are never reissued. The stale removal now returns 404 and changes nothing. | `test_stale_document_removal_cannot_delete_a_replacement`. Verified failing with the old schema. | Fixed |
| DEF-003 | Claude smoke test (before the first UI commit) | Requested every GET route through the Flask test client | 9 of 19 pages returned **500** with `jinja2.exceptions.UndefinedError: 'labels' is undefined` / `'csrf_token' is undefined`. | Macros imported with `{% from "_macros.html" import … %}` do not receive the template context by default. | Import macros `with context`. | `test_every_get_route_leaves_the_database_unchanged` asserts every GET route returns 200/404/405, never 500. Browser runs also fail on any console error. | Fixed |
| DEF-004 | Codex source review R3-03 | Reported by Codex, then reproduced by Claude with a temporary `MOBLAB_INSTANCE_DIR` and a dummy listener on 127.0.0.1:5058 (no demo database involved) | `./launch_demo.command --reset` with 5058 busy **backed up and reseeded first** (marker row gone, backup file created) and only then exited with "already in use". | The launcher ran the reset/seed step before the busy-port check, and `moblab reset` had no guard against a live server. | (1) The launcher checks the busy port before any reset or seed. (2) `moblab run` holds a shared `flock` on `<db>.runlock` for its lifetime, and `moblab reset` needs an exclusive lock, so it refuses (exit 3, "Nothing was changed") while any server on any port has that database open. POSIX only (macOS/Linux). | `test_launcher_on_busy_port_changes_nothing` (verified failing on the old launcher), `test_cli_reset_refuses_while_a_server_holds_the_database`. | Fixed |
| DEF-005 | Claude browser review of real screenshots | Viewed the 390 px and 1440 px screenshots from the Chromium run | At 390 px, table columns collapsed to one or two letters per line ("SUBSCRIP TION", "PE -0 1"). At 1440 px, the impact and examples tables were wider than the card, so columns were clipped. The automated overflow check still passed, because the page itself never overflowed. | `overflow-wrap: anywhere` on `body` let table min-content widths shrink to single letters, and long unbreakable codes widened tables. The layout check only measured page overflow. | `overflow-wrap: break-word`. Tables get a minimum width and scroll inside their wrapper on phones. A `wbr` filter adds break points after `_`/`;` in codes. The actor select can shrink. | The browser tests now also fail on clipped or squashed table headers at any width, and on any table needing sideways scrolling at desktop width (the check was confirmed to detect scrolling at 390 px). | Fixed |
| DEF-006 | Claude, while turning the corrected demo script into a literal single-window browser test | `test_demo_script_main_path_in_one_window` saw an unexpected console error: `405 (METHOD NOT ALLOWED)` | After a refused action (for example `POLICY_MIGRATION_REQUIRED`), the page is rendered by the POST URL `/cases/MOB-0003/decision`. The browser demo-path test now asserts that the only console error is the intended 409. | Fixed |

## Test-harness defects (bugs in test code, not the product)

| ID | Symptom | Cause | Fix |
|---|---|---|---|
| TH-01 | First full run: 17 failures with `TypeError: Lab.refused() got an unexpected keyword argument` | The helper `Lab.refused(code, fn, *args)` did not forward `**kwargs`. | It now forwards `**kwargs`. |
| TH-02 | Two tests failed with `TypeError` inside convoluted conditional loops | An over-compact test loop passed arguments in the wrong shape. | The loops were rewritten as explicit calls. |
| TH-03 | During manual verification, the reviewer's case page looked identical to the anonymous one | Flask `session_transaction()` sets the cookie for `localhost`, but the probe sent `Host: 127.0.0.1`, so the session cookie was not sent back. The app was correct. | Tests use the default test-client host. |
| TH-04 | Review helper killed its own shell (exit 144) | `pkill -f "port 5071"` matched the shell's own command line. | Servers are stopped by PID. |
| TH-05 | First final recording (on the clean code commit): **2 failed, 1 skipped** of 116. `test_markdown_links_resolve` failed for `README.md` (screenshot) and `docs/07_release_recommendation.md` (link to 06), and the replay check was skipped. | Generated outputs (screenshots, `docs/06`, the replay) are written only after pytest finishes, so on a checkout without them the doc-link checks run too early. The product was not at fault. | A documented two-pass recording (first pass generates, second pass is the recorded run). The instructions are in `docs/06_test_evidence.md` → Reproduce. |

## Documentation defects

| ID | Found by | Problem | Fix |
|---|---|---|---|
| DOC-01 | Codex documentation review of `docs/08_demo_script.md` | The manual script used "two browser windows" for the stale-tab refusal. Windows of one browser profile share the session cookie, so switching the other window to Alex would make the old Sam form submit as Alex (`FORBIDDEN_ROLE`, not `STALE_REVISION`). The script also moved the clock without saying which actor is allowed, and did not say to stop a running server before `--reset`. | The main path now uses one window with explicit actor switches. The stale-tab check is an optional exercise with a normal window plus a private window (separate cookie jars), with "do not refresh" and "switch back" points. The script says any non-auditor may move the clock, and to stop the server before a reset. The same fixes were made on the demo page, the lab page and the Chinese guide. The script is executed literally by `test_demo_script_main_path_in_one_window`, `test_tabs_of_one_browser_share_the_actor` (proves the caveat) and `test_demo_script_optional_stale_tab_exercise`. That work also found DEF-006. |
